# Агенты ub-mode — краткая документация

Проект использует адаптацию [ub-mode](https://github.com/unclebob/ub-mode) Uncle Bob'а. Каждое изменение проходит
три стадии: **сначала заставь работать** (сначала падающая проверка), **потом сделай правильно** (гейты качества,
рефакторинг) и **практика** (лог, маленькие коммиты с доказательством).

Все правила лежат в одном месте: [`.claude/skills/ub-mode/SKILL.md`](skills/ub-mode/SKILL.md). Агенты содержат только
свою процедуру и формат отчёта, а за правилами ссылаются на разделы скилла (`§ …`).

## Как запустить

- `/ub-mode` в Claude Code. Скилл сам распределит работу по агентам.
- Можно позвать агента и напрямую: «используй `ub-scenario-author` для `GET /users/get/{id}` с 404».

Агенты **не коммитят и не пушат**. Они возвращают лог, список файлов и доказательства. Коммит делает основной
диалог, после проверки `ub-reviewer`. Пуш выполняется только по вашей просьбе.

## Агенты

| Агент | Когда | Что ему дать | Что вернёт |
|---|---|---|---|
| `ub-scenario-author` | Новое или изменённое поведение API: сценарий, шаги, сервис, контракт, билдер | операцию, feature-файл, критерий «готово» | лог; изменённые файлы; по каждому JSON-ответу 2xx — контракт *found*/*added*; red → green или прогоны с намеренно неверными ожиданиями |
| `ub-unit-tdd` | Код фреймворка: чистые модули `src/` (utils, assertions, contracts, builders) и `tools/` | модуль и нужное поведение или баг | red перед каждым green, итоги `npm run unit`, счёт `gate:mutate` с объяснением выживших мутантов |
| `ub-gatekeeper` | После изменений, или чтобы погасить долг из `quality/*-baseline.json` | изменённые файлы или «топ-N нарушителей» | находки и выбранные исправления, гейты до и после, размер baseline до и после |
| `ub-reviewer` | Перед каждым коммитом и перед слиянием | `--staged` и предлагаемое сообщение коммита, или диапазон `<base>...<head>` | находки уровней blocker / should fix / nit с `file:line` и вердикт |

У `ub-reviewer` нет Edit и Write. Он не меняет отслеживаемые файлы, только запускает офлайн-проверки.

### Типовой цикл

1. `ub-scenario-author` или `ub-unit-tdd` — пишет код.
2. `ub-gatekeeper` — проверяет гейты по затронутым файлам.
3. `ub-reviewer` с `--staged` — проверяет перед коммитом.
4. Коммит (Why / What / Proof).

### Как `ub-scenario-author` пишет сценарий

1. Сначала сценарий, до контракта, билдера, пути и шагов.
2. `npm run test:dry`.
   - Если все шаги переиспользованы, прогон должен пройти, и **живая проверка идёт сразу**, ничего не меняя.
   - Если нужна новая фраза шага, неопределённой должна быть только она. Потом схема данных, затем клей.
3. Живой прогон: `npm run scenario -- "<заголовок>"`.
   - Прогон должен упасть на ассерте, по ожидаемой причине.
   - Если API уже ведёт себя правильно и прогон зелёный, нужно доказать, что ассерты «кусаются». Каждому ассерту, который решает исход, по очереди даётся неверное ожидание (у негативных — и статусу, и коду ошибки). Затем значения возвращаются обратно.
4. Сверка с реестром контрактов. Каждый ответ 2xx с JSON-телом должен иметь запись в `CONTRACTS_2XX`. Клиент молча пропускает ответы без контракта, поэтому живой прогон такую дыру не покажет. У ответов 204, без тела и бинарных (`GET /files/{id}/download`) контракта нет намеренно.

## Правила запуска

- **По одному в одном checkout.** Все агенты пишут общие артефакты (`reports/`, `allure-results/`), а живой API ограничен лимитами по IP.
- **Параллельно только в отдельных git worktree**, только офлайн и после `npm ci`.

## Команды

| Команда | Что проверяет |
|---|---|
| `npm run scenario -- "<заголовок>" [--dry]` | **один** сценарий (или все строки Outline) на живом API; `--dry` — только подсчёт |
| `npm run test:dry` | все шаги определены, нет неоднозначных |
| `npm run unit` | офлайн unit-тесты (`node:test`) |
| `npm run gate:crap` | CRAP < 10 на функцию сверх baseline |
| `npm run gate:dry` | дублирование ≥ 0.8 сверх baseline |
| `npm run gate:mutate -- <файл> [--fn <имя>]` | тесты замечают внесённые ошибки |

## Ловушки

- **Не запускайте один сценарий так:**
  - `npx cucumber-js <feature>:<line>` — добавляет путь к `paths` профиля и гонит почти весь набор по живому API;
  - `--name "^…$"` — это регэксп, и заголовки с `( ) + ?` или `<плейсхолдерами>` молча ничего не находят, а 0 сценариев завершается с кодом 0.

  Используйте только `npm run scenario`: он экранирует заголовок, сначала делает dry-run и отказывается работать при 0 совпадений.
- **`@Bug`, `@Ignore` и сценарии без `@Run` не выбираются.** Фильтр тегов профиля применяется всегда, а `--tags` его не обходит.
- **Baseline — это храповик.**
  - Гейт падает только на **новом** или **ухудшенном** нарушителе.
  - `--update` только сжимает baseline. Если есть NEW или WORSE, он откажется.
  - `--update --accept` — осознанное исключение, его причину нужно написать в коммите.
